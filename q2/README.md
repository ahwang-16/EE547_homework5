1. What clients would observe after a replacement if the signing key were in the image or on the instance:
If the JWT signing key was hardcoded inside the instance or randomly generated by the application at boot, replacing the EC2 instance would create a completely new cryptographic key. Tokens generated by the old instance would fail signature verification on the new instance, forcing all existing users to log in again immediately. By pulling the key from Parameter Store, replacements share identical state, and client tokens remain valid across server rebuilds.

2. What the tag check in launch.py guards against:
It prevents concurrently launching multiple instances that serve the same API without a load balancer. Because each Flask container manages its own in-memory state (the REQUEST_COUNTS dictionary) and exposes port 8080 directly on its public IP, running multiple instances would result in fragmented, inaccurate server statistics. It also serves as a cost-control safeguard to ensure only one billing resource is active at a time.

3. Why teardown.py --all deletes in the order it does, and what fails if two steps are swapped:
Resources are deleted in strict reverse-dependency order. For example, AWS rejects deleting a Security Group that is actively attached to a running EC2 ENI (DependencyViolation), so the instance must be terminated (Step 1) before the security group is deleted (Step 2). Similarly, AWS rejects deleting an IAM Role that is actively assigned to an Instance Profile, so the Role must be unlinked and the Instance Profile deleted (Step 3) before the Role itself is deleted (Step 4).

4. One failure you hit in user data, and how you found it:
During initial testing, the Docker container failed to launch because it could not retrieve the JWT_SECRET. I discovered this by SSHing into the EC2 instance and reading /var/log/user-data.log. The log showed a botocore.exceptions.NoCredentialsError because I had forgotten to set HttpPutResponseHopLimit=2. Without this hop limit, the Docker bridge network (which counts as an additional network hop) blocked the container from authenticating with the IMDSv2 metadata endpoint.
